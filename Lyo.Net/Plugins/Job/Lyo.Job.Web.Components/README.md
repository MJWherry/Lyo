# Lyo.Job.Web.Components

Blazor / MudBlazor dashboard for the Lyo job stack. Drop `JobManagement` on a host page for Statistics, Definitions, Schedules, Runs (progress and SLA breach indicators), worker
registry, and workflow views. Uses an injected `IApiClient` and a configurable base route prefix.

The Workers datagrid uses REST heartbeats plus optional AutoRefresh (on by default) for live registry updates.

Targets server-side or interactive Blazor on `net10.0` and pulls in MudBlazor `>= 9.3`.

This package is a Razor component library. It has no `AddXxx` DI registration. The host must already register `IApiClient`.

## Examples

### Architecture

```mermaid
flowchart LR
    UI[JobManagement tabs] --> API[IApiClient → Job API]
    API --> MQ[job.events exchange]
```

## Top-level entry point

```razor
@using Lyo.Job.Web.Components

<JobManagement BaseRoute="Job" StatisticsRoute="api/job-stats/recent" />
```

| Parameter         | Notes                                                                                          |
|-------------------|------------------------------------------------------------------------------------------------|
| `BaseRoute`       | Route prefix for job endpoints. Required. Defaults to `"Job"`.                                 |
| `StatisticsRoute` | Optional URL returning `SpJobStatistic` rows. When omitted, the stats tab shows an info alert. |

`MudTabs` on `JobManagement` expose Statistics, Definitions, Schedules, Runs, Workers, and Workflows.

## Formatter and condition context

A formatter-typed job parameter is a template, so authors need the keys that will actually resolve.

**Definition editor** — `JobFormatterContext.Build(definition, latestRuns, schedule)` builds that key list and matches both runtime stages:

- **Scheduler** (`JobScheduler.BuildTemplateData`): `Definition`, `LastRun`, `LastSuccessfulRun`, `LastFailedRun`, `Schedule`, plus flattened `{prefix}_Result_{key}` /
  `{prefix}_Parameter_{key}` and `Schedule_Parameter_{key}` entries.
- **Worker** (`JobWorkerParameterFormatter.SeedJobRun`): the `jobrun` bag (run properties and a `Parameters` map). `{jobrun.parameters.emailTo}` reads from that map.

**Workflow step editor** — `JobWorkflowFormatterContext.Build(step, definition, workflow, inputKeys, dependencies)` builds the bag for one step of a workflow, which is a different
shape: it offers `Workflow.*`, `Input.{key}`, `CurrentStep.*`, `Definition.*`, and `Step.{name}.*` for each dependency. It goes through the same `JobContextBag.WithWorkflowStep`
seeder the engine uses at run time, and `JobWorkflowFormatterContextTests` asserts the editor offers every key the engine seeds, so the two cannot drift.
`JobWorkflowFormatterContext.Paths` walks that bag into the condition editor's field list, sizing the catalog budget to the dependency count so a step with several upstreams is not
truncated.

Views receive the bag as `FormatterContext`. Host-supplied `AddContext` keys arrive on a separate path through `AddLyoFormatterValueEditor`. Steps and definitions that have never
run still autocomplete on the run paths because `LyoSampleShape` substitutes for the missing `JobRunRes`.

## `JobColorHelper`

One static helper applies the same colors and icons to job state, result, and log level.

| Member                                       | Returns / behavior                                                     |
|----------------------------------------------|------------------------------------------------------------------------|
| `ForState(JobState)`                         | MudBlazor `Color` mapping.                                             |
| `ForWorkerState(JobWorkerInstanceState)`     | Running→Success, Draining→Warning, Stopped→Default.                    |
| `ForResult(JobRunResult?)`                   | Success / warning / error colors.                                      |
| `ForLogLevel(JobLogLevel)`                   | Trace/Debug→Default, Info→Info, Warning→Warning, Error/Critical→Error. |
| `StateIcon` / `ResultIcon`                   | Material icon names.                                                   |
| `FormatDuration` / `FormatDurationFromDates` | Human-readable durations.                                              |
| `GetEnumDescription<T>(T value)`             | `[Description]` attribute or field name.                               |
